Best architecture for low-cost Replit apps

For most of your applications:

Frontend
React/Vite build
publish as Static if it can call your backend API separately
Backend API
Express or Fastify
publish as Autoscale
no polling every few seconds unless absolutely needed
cache hot GET responses
batch expensive DB work
do not run loops in the background forever
Jobs
invoice reminders
sync jobs
cleanup jobs
AI batch processing
publish as Scheduled Deployment or trigger protected endpoints from a scheduled deployment

That aligns with Replit’s current deployment model and keeps you on-platform.

2) src/lib/cache.ts

This cuts repeated DB/API hits.

type CacheEntry<T> = {
  value: T;
  expiresAt: number;
};

export class TtlCache {
  private store = new Map<string, CacheEntry<unknown>>();

  get<T>(key: string): T | null {
    const entry = this.store.get(key);
    if (!entry) return null;

    if (Date.now() > entry.expiresAt) {
      this.store.delete(key);
      return null;
    }

    return entry.value as T;
  }

  set<T>(key: string, value: T, ttlMs: number): void {
    this.store.set(key, {
      value,
      expiresAt: Date.now() + ttlMs,
    });
  }

  del(key: string): void {
    this.store.delete(key);
  }

  clear(): void {
    this.store.clear();
  }
}

export const appCache = new TtlCache();
3) src/lib/inFlight.ts

This prevents duplicate simultaneous expensive requests.

const inFlight = new Map<string, Promise<unknown>>();

export async function singleFlight<T>(
  key: string,
  factory: () => Promise<T>
): Promise<T> {
  const existing = inFlight.get(key);
  if (existing) return existing as Promise<T>;

  const promise = factory()
    .finally(() => {
      inFlight.delete(key);
    });

  inFlight.set(key, promise);
  return promise;
}
4) src/lib/rateLimit.ts

Very cheap in-memory limiter. Good for autoscale apps where you just want basic protection.

import type { Request, Response, NextFunction } from "express";
import { config } from "../config";

type Bucket = {
  count: number;
  resetAt: number;
};

const buckets = new Map<string, Bucket>();

export function rateLimit(req: Request, res: Response, next: NextFunction) {
  const ip =
    (req.headers["x-forwarded-for"] as string)?.split(",")[0]?.trim() ||
    req.socket.remoteAddress ||
    "unknown";

  const key = `${ip}:${req.path}`;
  const now = Date.now();

  const bucket = buckets.get(key);
  if (!bucket || now > bucket.resetAt) {
    buckets.set(key, {
      count: 1,
      resetAt: now + config.rateLimitWindowMs,
    });
    return next();
  }

  bucket.count += 1;

  if (bucket.count > config.rateLimitMax) {
    return res.status(429).json({
      error: "Too many requests",
      retryAfterMs: bucket.resetAt - now,
    });
  }

  return next();
}
5) src/lib/requestCache.ts

Use this on hot GET routes.

import type { Request, Response, NextFunction } from "express";
import { appCache } from "./cache";
import { config } from "../config";

export function requestCache(ttlMs = config.defaultCacheTtlMs) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (req.method !== "GET") return next();

    const key = `http:${req.originalUrl}`;
    const cached = appCache.get<unknown>(key);

    if (cached !== null) {
      return res.json({
        ...((cached as object) || {}),
        _cached: true,
      });
    }

    const originalJson = res.json.bind(res);

    res.json = (body: unknown) => {
      if (res.statusCode >= 200 && res.statusCode < 300) {
        appCache.set(key, body, ttlMs);
      }
      return originalJson(body);
    };

    next();
  };
}
6) src/lib/cooldown.ts

Stops expensive actions from firing repeatedly.

const lastRunByKey = new Map<string, number>();

export function shouldRun(key: string, cooldownMs: number): boolean {
  const now = Date.now();
  const last = lastRunByKey.get(key) || 0;

  if (now - last < cooldownMs) return false;

  lastRunByKey.set(key, now);
  return true;
}
7) src/db.ts

Use a single pool, not too many connections.

import { Pool } from "pg";
import { config } from "./config";

if (!config.databaseUrl) {
  throw new Error("DATABASE_URL is required");
}

export const pool = new Pool({
  connectionString: config.databaseUrl,
  max: 5, // keep low for cost and connection pressure
  idleTimeoutMillis: 30_000,
  connectionTimeoutMillis: 10_000,
});

export async function query<T = unknown>(text: string, params: unknown[] = []) {
  const result = await pool.query(text, params);
  return result.rows as T[];
}

This matters because oversized pools and chatty query patterns are a common source of wasted DB usage. Replit’s docs also point you to usage monitoring for database storage and deployment usage.

8) src/server.ts

This gives you a low-cost API shape.

import express from "express";
import compression from "compression";
import helmet from "helmet";
import { config } from "./config";
import { rateLimit } from "./lib/rateLimit";
import { requestCache } from "./lib/requestCache";
import { singleFlight } from "./lib/inFlight";
import { shouldRun } from "./lib/cooldown";
import { query } from "./db";

const app = express();

app.use(helmet());
app.use(compression());
app.use(express.json({ limit: "1mb" }));
app.use(rateLimit);

// Health route for monitoring
app.get("/health", (_req, res) => {
  res.json({
    ok: true,
    env: config.nodeEnv,
    ts: new Date().toISOString(),
  });
});

// Example hot list endpoint with cache + single-flight
app.get("/api/customers", requestCache(60_000), async (_req, res, next) => {
  try {
    const data = await singleFlight("customers:list", async () => {
      return query(
        `SELECT id, name, email, created_at
         FROM customers
         ORDER BY created_at DESC
         LIMIT 100`
      );
    });

    res.json({ items: data });
  } catch (err) {
    next(err);
  }
});

// Example expensive endpoint guarded from repeated trigger spam
app.post("/api/reports/rebuild", async (req, res, next) => {
  try {
    const key = `rebuild:${req.ip || "unknown"}`;

    if (!shouldRun(key, config.expensiveRouteCooldownMs)) {
      return res.status(202).json({
        ok: false,
        message: "Already triggered recently. Please wait before retrying.",
      });
    }

    // Do lightweight queue insert instead of full work inline
    await query(
      `INSERT INTO jobs (type, payload, status, created_at)
       VALUES ($1, $2::jsonb, $3, NOW())`,
      ["rebuild-report", JSON.stringify(req.body || {}), "pending"]
    );

    res.json({ ok: true, queued: true });
  } catch (err) {
    next(err);
  }
});

// Protected scheduled endpoint
app.post("/internal/jobs/run", async (req, res, next) => {
  try {
    const token = req.headers["x-cron-secret"];
    if (!config.cronSecret || token !== config.cronSecret) {
      return res.status(401).json({ error: "Unauthorized" });
    }

    const jobs = await query<{
      id: string;
      type: string;
      payload: unknown;
    }>(
      `SELECT id, type, payload
       FROM jobs
       WHERE status = 'pending'
       ORDER BY created_at ASC
       LIMIT 25`
    );

    for (const job of jobs) {
      try {
        await query(`UPDATE jobs SET status = 'processing' WHERE id = $1`, [job.id]);

        switch (job.type) {
          case "rebuild-report":
            // Put your real work here
            break;
          default:
            break;
        }

        await query(
          `UPDATE jobs
           SET status = 'done', completed_at = NOW()
           WHERE id = $1`,
          [job.id]
        );
      } catch (jobErr) {
        await query(
          `UPDATE jobs
           SET status = 'failed', error = $2
           WHERE id = $1`,
          [job.id, jobErr instanceof Error ? jobErr.message : "Unknown error"]
        );
      }
    }

    res.json({ ok: true, processed: jobs.length });
  } catch (err) {
    next(err);
  }
});

// Minimal request timing
app.use((req, res, next) => {
  const start = Date.now();

  res.on("finish", () => {
    const ms = Date.now() - start;
    if (ms >= config.logSlowRequestsMs) {
      console.log(`[slow] ${req.method} ${req.originalUrl} ${res.statusCode} ${ms}ms`);
    }
  });

  next();
});

// Error handler
app.use((err: unknown, _req: express.Request, res: express.Response, _next: express.NextFunction) => {
  console.error(err);
  res.status(500).json({
    error: "Internal server error",
    message: err instanceof Error ? err.message : "Unknown error",
  });
});

app.listen(config.port, () => {
  console.log(`API listening on port ${config.port}`);
});
SQL for lightweight job queue

Use your DB instead of keeping a worker process alive 24/7.

migrations/001_jobs.sql
CREATE TABLE IF NOT EXISTS jobs (
  id BIGSERIAL PRIMARY KEY,
  type TEXT NOT NULL,
  payload JSONB NOT NULL DEFAULT '{}'::jsonb,
  status TEXT NOT NULL DEFAULT 'pending',
  error TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  completed_at TIMESTAMPTZ
);

CREATE INDEX IF NOT EXISTS idx_jobs_status_created_at
  ON jobs (status, created_at);

This lets your Scheduled Deployment wake up, process pending jobs, and shut back down instead of paying for an always-on worker. Replit explicitly supports scheduled runs for this kind of use.

Frontend changes that save money immediately

A lot of Replit cost waste comes from noisy frontend behavior, not server size.

Bad
polling every 5 seconds
reloading dashboard counts on every tab switch
loading huge tables by default
re-fetching unchanged data
running AI generation automatically on page load
Better
// api.ts
type FetchOptions = {
  ttlMs?: number;
};

const memoryCache = new Map<string, { expiresAt: number; value: unknown }>();

export async function cachedFetch<T>(url: string, options: FetchOptions = {}): Promise<T> {
  const ttlMs = options.ttlMs ?? 30_000;
  const now = Date.now();

  const cached = memoryCache.get(url);
  if (cached && cached.expiresAt > now) {
    return cached.value as T;
  }

  const res = await fetch(url, {
    credentials: "include",
    headers: { "Content-Type": "application/json" },
  });

  if (!res.ok) {
    throw new Error(`Request failed: ${res.status}`);
  }

  const data = (await res.json()) as T;
  memoryCache.set(url, { value: data, expiresAt: now + ttlMs });
  return data;
}

Use it like:

const stats = await cachedFetch("/api/dashboard/stats", { ttlMs: 60000 });

And for dashboards:

counts: 60–120 second refresh
activity feeds: manual refresh or 30–60 second refresh
reports: generate only on button click
search: debounce 300–500ms
File handling pattern for Replit

Replit says not to rely on a deployed app’s filesystem for persistent app data; use database or object storage instead.

So:

Do not do this
fs.writeFileSync(`/tmp/uploads/${file.name}`, fileBuffer);
Do this
metadata in SQL DB
actual files in App Storage
serve signed or controlled URLs
compress images before upload
store only one original + one thumbnail, not five versions unless needed
