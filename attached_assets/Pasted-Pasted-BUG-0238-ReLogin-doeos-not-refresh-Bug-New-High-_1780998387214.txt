Description

**Steps to Reproduce:**
1. Log in as User A.
2. Log out from User A and log in as User B without refreshing the page.
3. Attempt to perform an action (e.g., cancel a correction request) that should be tied to User A's session.

**Expected Behavior:**
After logging out and logging in as a new user, the application should refresh and load the data specific to the newly logged-in user.

**Actual Behavior:**
The page does not refresh after logging out. As a result, actions specific to User A's session can still be viewed and performed by User B until the page is manually refreshed.

**Additional Context:**
- The issue allows unauthorized access to data and actions from the previously logged-in user.
- Detected when attempting to cancel a correction request from User A’s data while logged in as User B.
- The bug may pose serious security risks if sensitive data or actions are accessible across sessions.

AI Analysis

### Analysis
#### 1) Part of the App Affected:
The session management during user login/logout is not functioning correctly. Specifically, the issue affects the user authentication flow, user data loading, and session isolation, leading to unauthorized access between user sessions without a page refresh.

#### 2) Root Cause Analysis:
Based on the report description, it seems that:
- The app doesn’t explicitly clear or reload the session, cached data, or state properly during the logout process.
- User-specific data and actions are still being tied to the previous session (User A) even after the authentication change (to User B).
- Without a page refresh, the application retains the old session data and allows interactions with it mistakenly under User B’s session.

This is most likely caused by:
- Failure to reset global state or in-memory state management (e.g., Redux, Context API, or other state-management tools) after logout.
- Lack of server-side session invalidation and data fetch to refresh the application’s state for the new user.
- Improper handling of session cookies or tokens that are not invalidated during logout.

#### 3) Recommended Fix or Next Steps:
- Ensure the `logout` operation clears all session-related data stored in the application state (e.g., localStorage, Redux state, etc.).
- Force a reload of user-specific data immediately after login (`login` and `logout` events should trigger a full reset of relevant state).
- Double-check server-side APIs for session invalidation logic. Ensure that logging out properly terminates the old session and requires a new data fetch for the newly logged-in user.
- Verify all caches (both application-level and browser-level) are cleared upon login/logout transitions.
- Add integration tests to simulate multiple login/logout scenarios, verifying session isolation and data integrity.
- In critical areas like canceling correction requests, validate user permissions server-side before allowing sensitive actions.

Since the bug poses a potential security risk (unauthorized access), prioritize fixing this issue promptly.
