Allow multiple Departments and Locations for Each Employee

Description

**Steps to Reproduce:**
1. Navigate to the "Employee" page.
2. Open the "Basic Info" tab for any employee.
3. Attempt to assign multiple departments and locations to the employee.

**Expected Behavior:**
The system should allow users to assign multiple departments and multiple locations to a single employee under the "Basic Info" tab.

**Actual Behavior:**
Currently, only a single department and a single location can be selected for an employee. There is no feature or mechanism to associate multiple departments or locations with the same employee.

**Additional Context:**
- This limitation restricts the ability to handle employees who work across departments or locations.
- The issue affects flexibility for organizations with dynamic workforce structures.
- The enhancement should consider how multiple department and location assignments are displayed, stored, and used in downstream processes or reports.

AI Analysis

### Analysis of the Bug Report

1. **Part of the App Affected:**
   - The "Employee" module, specifically the **Basic Info** tab, where department and location assignments are managed.

2. **Issue Description:**
   - The UI currently offers a dropdown (single-selection field) for "Department" and "Location," restricting users to a single department and location assignment per employee.
   - Employees working across multiple departments and locations cannot be flexibly managed using the current system.

3. **Root Cause Analysis:**
   - **Frontend Limitation:** 
     The dropdown components are configured for single selection only. To allow multiple selections, they need to be transitioned to components (like multi-select dropdowns or checkboxes) that support multiple entries.
   - **Backend Limitation:** 
     The database schema is likely designed with a 1:1 relationship between employees and departments/locations. There may not yet be an associative table (e.g., `employee_departments` or `employee_locations`) to handle many-to-many relationships.
   - **Integration/Validation Impact:** 
     The downstream processes (reporting, API requests, or system modules) might not currently support multiple department/location logic for a single employee, causing potential future mismatches or errors.

4. **Recommendations:**
   - **Frontend Changes:**
     - Replace the single-select dropdowns with multi-select components for both "Department" and "Location."
     - Update the display logic on the UI to handle multiple department/location values.
   - **Backend/Database Changes:**
     - Introduce pivot tables (e.g., `employee_departments` and `employee_locations`) establishing a many-to-many relationship between employees and departments/locations.
     - Modify API payloads and validations to support multiple entries for these attributes.
   - **Testing and Downstream Integration Considerations:**
     - Update the reporting module, API responses, and other dependent services to accommodate changes.
     - Run regression and integration tests to ensure no disruptions.
   - **Visual Enhancements:**
     - Clearly display all assigned departments/locations in the "Basic Info" tab.
     - Allow users to easily modify or remove assignments.

5. **Screenshot Analysis:**
   - The "Basic Information" section shows single-select dropdowns for "Department" and "Location."
   - There's no functionality allowing assigning or displaying multiple values, confirming the current limitation.
