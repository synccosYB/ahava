Description

**Steps to Reproduce:**
1. Navigate to the "Create New Policy" window within the application.
2. Proceed to the "Assignment" step.
3. Attempt to interact with the "Target" dropdown to select an assignment.

**Expected Behavior:**
The "Target" dropdown in the "Assignment" step should allow users to select an assignment for all policy types (e.g., PTO, Leave, Attendance, etc.) enabling smooth progression to subsequent steps.

**Actual Behavior:**
The "Target" dropdown appears disabled, preventing assignment selection for all policy types. As a result, users cannot proceed to the next steps to test or set up the policy correctly.

**Additional Context:**
This issue occurs universally for all policy types, creating a bottleneck in the policy creation workflow. Resolving this is critical to ensuring proper testing and setup of policies.

Resolution

Task #312 is merged and resolved. Here's what it fixed:

The problem: In the Create New Policy wizard, the "Target" dropdown was permanently unusable for some admins — the Level options (Company / Location / Department / Employee / Role) showed up disabled, so you couldn't assign a policy to anyone.

Why it happened: Each Level pulled its list from a separate endpoint that required a granular view permission (company.view, locations.view, departments.view, users.view). But opening the policy wizard itself only requires being an admin. So any admin who didn't happen to hold one of those view permissions got a silent 403 → empty list → disabled Level. Only the Super Admin worked, because it bypasses permission checks.

The fix: A single consolidated endpoint (/api/policy-assignment-targets) now loads all five target lists at once, gated by the same admin check that lets you open the wizard in the first place. On top of that, Levels no longer disable themselves when a list is empty — they stay clickable and show a helpful "No X options are available" message instead of silently locking you out.

Net result: every admin who can open the policy wizard can now actually pick targets and assign policies. No action needed on your side — it's live after the next deploy.

Two optional follow-ups were proposed alongside it (not yet done): #313 (drive policy management off permissions instead of the legacy admin flag) and #314 (an automated test so this can't silently break again). Want me to queue either of those, or are you good?
